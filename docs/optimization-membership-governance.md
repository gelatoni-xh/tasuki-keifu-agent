# Membership 治理拆分与日期精度优化

日期：2026-11-19。范围：Agent V2 本地实现与回归验证，尚未部署、尚未用新赛事评估业务效果。

## 问题与案例

2025年第66回东日本实业团驿传原始80项待确认，经人工复核分三轮处理69、6、5项，当前已结案。人工修复不计为Graph自动解决，也不据此宣称新版本自动解决率。

- 实业团隐式提示将赛事日当作开始日期，并断言ongoing，导致既有履历起点与赛事日不同也进入重型研究。
- 重型模型认为现有履历合理时，因为没有返回非空日期修正，仍被保留为unresolved。
- 同一个人的不同finding分别研究，缺少完整转会时间线，产生重复请求。
- 原研究契约只能表达具体日期，数据库年份字段没有完整读写，促使模型追求不必要的精确日期。
- NTT沿革证明旧队历史被新体制继承，但不是所有同集团组织都应合并；存量组织合并不在本次自动化范围。
- 人物合并后可能留下重复Membership或漏掉当前已确认学校/实业团关系；多条重复记录的来源需要完整保留。

## 新流程

`prepare_membership_context → membership_rules → collect_membership_conflicts`

没有真实冲突直接进入`finalize_membership`；有冲突进入：

`membership_deep_research → validate_membership_decisions → finalize_membership`

完整导入与membership_only共用该子图，阶段状态可checkpoint；只有重型研究阶段调用模型并可联网。无新增轻量节点，无回边；同人全部membership_conflict合并为一个研究项，提供完整履历、相关冲突与已有历史证据。既有单请求有限重试规则保持不变。

## 五项约定

1. 赛事日只作为所属观察，包含DNS、DNF，不作为入离队日或持续雇佣证明。确认的学校、实业团可补空日期关系；club、company、unknown不建立关系。
2. `keep_membership`是有效终态，必须有核验后的证据与理由；不修改日期也可resolved。但范围越界、无证据、无效时间及仍然存在的明确互斥重叠不能被直接忽略。
3. 起止日与年份分别表达。年级/学校阶段仍按既有规则推算；企业转会仅知道年份时不生成1月1日、4月1日等假日期。未知日期保持空。公告日、赛事日不能代替生效日。清理错误精确日期需显式clear标记，null本身继续表示不修改，兼容原契约。年份级修正会移除错误具体日。推算依据须标inferred。
4. 优先利用规范名称与已有别名，候选召回包含别名前缀；组织联网研究核查官方沿革、旧称与继承关系，不能靠暂定选手匹配循环证明组织相同。多个存量组织候选只产生informational维护线索，主图不生成merge_organization。已确认本次映射可以继续，存量合并独立维护。受影响选手重评一次，不重新触发组织研究。
5. 对受影响人物的全部规范ID履历去重，不仅检查本次代表队。仅关系、角色、学部/学科/届别、时间、日期依据、结束状态和互斥组均一致时自动删除重复。不同履历段保留。所有来源留在保留记录和删除审计中，补齐当前已确认的学校/实业团关系；不因没有参赛成绩自动删除Membership，不以同名本身授权人物合并。

## 验证与发布边界

回归覆盖：赛事日误报、空日期/DNS关系、大学到实业团、同人多冲突单请求、维持原状、年份级和未知日期修正、越界/不完整修正的原子拒绝、所有受影响履历去重、角色不同不去重、来源累积与重复执行幂等、校验阶段重启不重复调用模型、旧别名匹配和禁用存量组织自动合并。

使用隔离的临时PostgreSQL执行真实迁移链及writer集成验证；不访问生产数据库，不调用实际外部模型。真实新赛事的耗时、tokens、重型比例与unresolved变化需在后续试跑验证，本轮没有业务提升数字。

本次节点名变更不将旧版未完成子图checkpoint直接视作兼容；发布时先确认无活动批次。已有完整历史计划与邮件不重写为新版自动结果。
